Héberger votre domaine sur Azure DNS

Faire en sorte que www.monsite.com mène à ton serveur dans Azure : la zone DNS, la délégation chez le registraire, les enregistrements, les alias, et les zones privées pour tes VNet.

⏱ Lecture : 8 min · module complet 🎯 Zones publiques et privées : souvent à l'examen
💡
À retenir : Azure DNS héberge ta zone, il ne vend pas le nom de domaine. Tu achètes le nom chez un registraire, tu crées la zone dans Azure, puis tu remplaces les serveurs de noms chez le registraire par les 4 serveurs NS d'Azure : c'est la délégation.

Pour s'en souvenir : le répertoire des expéditions 🚛

📒 Le DNS

  • DNS = le répertoire qui traduit « Terminal Laval » en adresse civique (le nom en IP)
  • Registraire = le bureau qui t'enregistre le nom de ta compagnie (GoDaddy, Namecheap…)
  • Zone DNS = ton cahier d'adresses pour ce nom, rangé chez Azure
  • Délégation (NS) = le registraire dit « pour toutes les adresses de cette compagnie, appelez le répartiteur Azure »
  • TTL = combien de temps un chauffeur peut garder l'adresse en mémoire avant de rappeler

🏷️ Les enregistrements

  • A = « Terminal Laval → 123 rue X » (nom → IPv4)
  • CNAME = « Entrepôt nord → voir Terminal Laval » (un surnom qui renvoie à un autre nom)
  • MX = où livrer le courrier (les courriels)
  • Alias = « l'adresse du quai principal, quelle qu'elle soit aujourd'hui » : si le quai déménage, le répertoire se met à jour tout seul
  • Zone privée = le répertoire interne affiché dans la cour, invisible de la rue

1 · Ce qu'est Azure DNS

✅ Ce qu'il fait

  • Héberge tes zones sur le réseau mondial de serveurs de noms de Microsoft (rapide et très disponible)
  • Même portail, mêmes identifiants, même facture que le reste d'Azure
  • Sécurité Azure : RBAC, journal d'activité, verrous sur la zone
  • Enregistrements d'alias vers des ressources Azure
  • Zones privées pour la résolution de noms dans tes VNet

❌ Ce qu'il ne fait pas

  • Acheter ou enregistrer un nom de domaine : ça se fait chez un registraire (ou via « Domaines App Service », un autre service)
  • Remplacer ton registraire : il reste propriétaire de l'enregistrement du nom

Scénario du module : Wide World Importers a acheté wideworldimports.com chez un registraire externe et veut le faire pointer vers son site hébergé dans Azure.

2 · Héberger un domaine public : les étapes

  1. Créer la zone DNS : abonnement, groupe de ressources, nom (wideworldimports.com). Les enregistrements NS et SOA sont créés automatiquement
  2. Noter les 4 serveurs de noms dans le jeu d'enregistrements NS (ex. ns1-04.azure-dns.com)
  3. Chez le registraire, remplacer les serveurs de noms par les 4 serveurs Azure : c'est la délégation
  4. Vérifier (10 min ou plus) en interrogeant le SOA : nslookup -type=SOA wideworldimports.com
  5. Ajouter tes enregistrements : un A pour le serveur web, un CNAME www si besoin

📦 Jeu d'enregistrements

Azure regroupe les enregistrements de même nom et même type dans un jeu. Ex. le jeu A www peut contenir plusieurs IP. Le TTL est défini par jeu (en secondes, minutes, heures…).

🔝 L'apex @

Le sommet de la zone : wideworldimports.com tout court, sans www. Dans le portail, on laisse le nom vide. On y trouve NS et SOA. On ne peut pas y mettre de CNAME : d'où les alias.

4 · Les enregistrements d'alias

🔗 Le principe

Au lieu d'écrire une IP en dur, l'enregistrement pointe vers une ressource Azure. Si l'IP de la ressource change, l'enregistrement suit tout seul. Si la ressource est supprimée, l'enregistrement se vide (pas d'enregistrement « orphelin » qui pointe vers une IP donnée à quelqu'un d'autre).

  • Types possibles : A, AAAA, CNAME
  • Fonctionne à l'apex (là où CNAME est interdit)

🎯 Cibles possibles

  • Adresse IP publique Azure (ex. celle d'un équilibreur de charge)
  • Profil Traffic Manager
  • Point de terminaison Azure CDN
  • Profil Front Door
  • Un autre jeu d'enregistrements de la même zone

Exercice du module : nom vide (apex), type A, alias Oui, ressource myPublicIP de l'équilibreur de charge.

5 · Zones DNS privées

🔒 Pour tes VNet

  • Invisibles sur Internet, pas de registraire
  • Donnent des noms à tes VM : vm1.private.contoso.com
  • Créer la zone (« Zones DNS privées »), puis Liaisons de réseau virtuel › Ajouter pour chaque VNet qui doit résoudre ces noms
  • C'est le « Virtual network link » de ton schéma du labo (private.contoso.com)

➕ examen : l'inscription automatique

  • En cochant Activer l'inscription automatique sur la liaison, chaque VM du VNet reçoit son enregistrement A tout seul (et il disparaît quand la VM est supprimée)
  • Un VNet peut être lié à plusieurs zones privées, mais l'inscription automatique n'est possible que vers une seule
  • Sans zone privée, Azure fournit déjà une résolution de base dans un VNet (noms des VM), mais pas entre VNet

6 · Les commandes

CommandeRôle
nslookup -type=SOA wideworldimports.comVérifier la délégation
nslookup www.wideworldimports.com ns1-04.azure-dns.comInterroger directement un serveur Azure (avant délégation)
az network dns zone create -g rg-dns -n wideworldimports.comCréer une zone publique
az network dns record-set a add-record -g rg-dns -z wideworldimports.com -n www -a 20.48.12.7Ajouter un enregistrement A
az network private-dns zone create -g rg-dns -n private.contoso.comCréer une zone privée
az network private-dns link vnet create -g rg-dns -z private.contoso.com -n lien-app -v app-vnet -e trueLier un VNet (-e true = inscription automatique)

PowerShell : New-AzDnsZone, New-AzDnsRecordSet, New-AzPrivateDnsZone, New-AzPrivateDnsVirtualNetworkLink. 💸 Une zone coûte environ 0,50 $US par mois : supprime le groupe de ressources après le labo (et l'équilibreur de charge et les VM de l'exercice d'alias).

Pièges d'examen

🪤« J'achète mon nom de domaine dans Azure DNS. »Non. Azure DNS héberge la zone. L'achat se fait chez un registraire.
🪤« J'ai créé la zone dans Azure, mon site répond déjà sur Internet. »Pas tant que tu n'as pas délégué : remplacer les NS chez le registraire par les 4 serveurs Azure.
🪤« Je mets un CNAME à l'apex pour pointer contoso.com vers mon CDN. »CNAME interdit à l'apex. Utilise un enregistrement d'alias.
🪤« Pour que mes VM se trouvent par leur nom dans une zone privée, je crée chaque enregistrement A à la main. »Active l'inscription automatique sur la liaison de réseau virtuel.
🪤« Mon VNet a l'inscription automatique sur deux zones privées. »Une seule zone avec inscription automatique par VNet (les autres liaisons en résolution seulement).
🪤« L'IP de mon équilibreur a changé, je dois corriger mon enregistrement A. »Pas si c'est un alias vers l'IP publique : il suit automatiquement.

Mini-quiz

Encart Terraform

🟪 Zone publique, alias à l'apex, zone privée liée

resource "azurerm_dns_zone" "pub" {
  name                = "wideworldimports.com"
  resource_group_name = azurerm_resource_group.labo.name
}

# Les 4 serveurs à donner au registraire
output "name_servers" { value = azurerm_dns_zone.pub.name_servers }

resource "azurerm_dns_a_record" "www" {
  name                = "www"
  zone_name           = azurerm_dns_zone.pub.name
  resource_group_name = azurerm_resource_group.labo.name
  ttl                 = 3600
  records             = ["20.48.12.7"]
}

# Alias à l'apex (@) vers une IP publique
resource "azurerm_dns_a_record" "apex" {
  name                = "@"
  zone_name           = azurerm_dns_zone.pub.name
  resource_group_name = azurerm_resource_group.labo.name
  ttl                 = 300
  target_resource_id  = azurerm_public_ip.lb.id
}

# Zone privée + liaison avec inscription automatique
resource "azurerm_private_dns_zone" "priv" {
  name                = "private.contoso.com"
  resource_group_name = azurerm_resource_group.labo.name
}

resource "azurerm_private_dns_zone_virtual_network_link" "app" {
  name                  = "lien-app-vnet"
  resource_group_name   = azurerm_resource_group.labo.name
  private_dns_zone_name = azurerm_private_dns_zone.priv.name
  virtual_network_id    = azurerm_virtual_network.app.id
  registration_enabled  = true
}
