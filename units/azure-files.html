Configurer Azure Files et File Sync

Partages de fichiers SMB/NFS, différence avec Blob, niveaux, authentification, instantanés, suppression réversible, Explorateur Stockage et Azure File Sync. Les notions marquées ➕ examen complètent le module.

⏱ Lecture : 8 min · module complet 🎯 Limites File Sync (1 cloud, 50 serveurs, 100 groupes) : questions fréquentes
💡
À retenir : Azure Files = un lecteur réseau dans le cloud (SMB port 445, NFS), monté par plusieurs machines. Instantanés : lecture seule, incrémentiels, 200 max. Suppression réversible : partage récupérable 1 à 365 jours. Azure File Sync garde une copie locale sur des serveurs Windows : 1 point cloud par groupe, jusqu'à 50 points serveur.

Pour s'en souvenir : le classeur du bureau de répartition 🚛

🗂️ Azure Files

  • Partage de fichiers = le classeur partagé du bureau, ouvert comme un lecteur Z: sur chaque poste
  • Port 445 (SMB) = la porte du bureau : beaucoup de fournisseurs Internet la bloquent depuis la maison
  • Instantané = la photocopie datée du classeur entier, en lecture seule
  • Suppression réversible = la boîte de récupération : un classeur jeté y reste 1 à 365 jours

🔄 Azure File Sync

  • Le classeur central est dans Azure ; chaque terminal régional (serveur Windows) en garde une copie de travail
  • Hiérarchisation cloud = on garde au terminal seulement les dossiers récents, les vieux restent au siège et reviennent sur demande
  • Agent = le commis installé à chaque terminal qui fait la navette

Azure Files = PaaS sans serveur : pas de VM ni de correctifs. Clients Windows, Linux et macOS. Chiffré au repos et en transit. Redondance = celle du compte. Sauvegarde avec Azure Backup. Les instantanés apparaissent dans les « Versions précédentes » de Windows.

🔌 Protocoles

  • SMB (Windows surtout) sur le port 445 : bloqué par beaucoup de FAI → cause n°1 des échecs de montage depuis chez soi. Solutions ➕ : VPN, ExpressRoute ou File Sync
  • NFS (Linux) : ➕ partages Premium seulement, accès par réseau privé
  • Un partage = un seul protocole ; un compte peut avoir des partages SMB et NFS

🔐 Authentification

  • Identité via SMB : AD DS local, Entra Domain Services ou Entra Kerberos, puis des rôles RBAC sur le partage (ex. « Contributeur de partage SMB de données de fichier de stockage »)
  • Clé d'accès : accès total, à ne pas partager
  • SAS : pour Azure Files, seulement par l'API REST depuis du code (pas pour monter un lecteur)

3 · Instantanés et suppression réversible

📸 Instantanés de partage

  • Copie en lecture seule, incrémentielle, du partage entier à un instant donné
  • Jusqu'à 200 instantanés par partage
  • Restaurer un fichier, un dossier ou tout le partage
  • ⚠️ Supprimer le partage supprime ses instantanés (sauf protection par Azure Backup)
  • Bon réflexe : un instantané avant chaque mise en production

🗑️ Suppression réversible

  • Activée au niveau du compte de stockage
  • Un partage supprimé reste récupérable 1 à 365 jours
  • Protège contre l'erreur humaine et les rançongiciels
  • ➕ Elle protège le partage ; pour un fichier effacé, on passe par un instantané

4 · L'Explorateur Stockage Azure

  • Appli de bureau Windows, macOS, Linux : blobs, fichiers, files d'attente, tables, disques, plusieurs comptes et abonnements
  • Se connecter : avec son abonnement, avec nom + clé d'un compte (attacher un stockage externe ou un cloud national : domaine « Autre »), avec une SAS de compte ou de service, ou à l'émulateur local (Azurite)
  • Il faut des droits ARM (voir le compte) et des droits sur les données
  • Les 2 clés servent à la rotation : tu bascules les applis sur key2, tu régénères key1, puis l'inverse

5 · Azure File Sync

ComposantRôleLimite
Service de synchronisation de stockageLa ressource Azure de base1 région, 100 groupes, 99 serveurs
Groupe de synchronisationCe qui est synchronisé ensemble1 point cloud + jusqu'à 50 points serveur
Point de terminaison cloudLe partage Azure FilesUn seul par groupe
Serveur inscritLien de confiance serveur ↔ serviceUn serveur = un seul service de synchro

Hiérarchisation cloud (cloud tiering) : seuls les fichiers récents restent sur le disque du serveur ; les autres deviennent des pointeurs et sont rapatriés à l'ouverture. Accès local en SMB, NFS ou FTPS, nombre de caches illimité dans le monde. ➕ Ordre de déploiement : 1. créer le partage Azure Files · 2. créer le service de synchronisation · 3. installer l'agent sur le serveur · 4. inscrire le serveur · 5. créer le groupe et le point cloud · 6. ajouter le point serveur.

6 · ➕ En CLI

az storage share-rm create -g rg-labo --storage-account stock1 -n partage --quota 100 --access-tier Hot
az storage share-rm snapshot -g rg-labo --storage-account stock1 -n partage
az storage account file-service-properties update -g rg-labo -n stock1 \
  --enable-delete-retention true --delete-retention-days 14
# Monter sous Windows (port 445 ouvert) :
net use Z: \\stock1.file.core.windows.net\partage /u:AZURE\stock1 <clé>

Pièges d'examen

🪤« Je ne peux pas monter mon partage depuis la maison : le partage est mal configuré. »Cause n°1 : le port 445 bloqué par le fournisseur Internet. VPN, ExpressRoute ou File Sync.
🪤« Je donne une SAS au comptable pour qu'il monte le lecteur Z:. »Pour Azure Files, la SAS sert seulement à l'API REST. Pour monter : identité (AD DS, Entra DS, Entra Kerberos) ou clé.
🪤« Un groupe de synchronisation avec deux partages Azure. »Un seul point de terminaison cloud par groupe.
🪤« Je mets mon point de terminaison serveur sur C:\. »Pas sur le volume système, et il faut du NTFS.
🪤« Je supprime le partage ; ses instantanés me sauveront. »Supprimer le partage supprime les instantanés. C'est la suppression réversible qui le récupère.
🪤« Un partage NFS sur un compte GPv2 Standard. »➕ NFS = partages Premium (compte FileStorage).
🪤« Les instantanés sont modifiables pour corriger un fichier. »Ils sont en lecture seule : on copie le fichier depuis l'instantané.

Encart Terraform

🟪 Partage de fichiers + suppression réversible

resource "azurerm_storage_account" "fichiers" {
  name                     = "stockfichiers123"
  resource_group_name      = azurerm_resource_group.labo.name
  location                 = "eastus"
  account_tier             = "Standard"
  account_replication_type = "ZRS"
  share_properties {
    retention_policy {
      days = 14                      # suppression réversible des partages
    }
  }
}
resource "azurerm_storage_share" "equipe" {
  name               = "partage"
  storage_account_id = azurerm_storage_account.fichiers.id
  quota              = 100           # Gio
  access_tier        = "Hot"         # TransactionOptimized, Cool, Premium
}
