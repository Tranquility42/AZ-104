Configurer des comptes de stockage

Les 4 services de stockage, les types de comptes, la redondance (LRS → RA-GZRS), les adresses et la sécurité réseau. Les notions marquées ➕ examen complètent le module.

⏱ Lecture : 8 min · module complet 🎯 Redondance : la question la plus fréquente du chapitre
💡
À retenir : un compte de stockage regroupe Blob, Files, Queue, Table sous une adresse unique. Prends Standard v2 sauf besoin de vitesse (Premium). La redondance : Local (1 bâtiment) → Zone (3 bâtiments) → Géo (+ autre région) → GZ (les deux). RA- = lecture de la copie secondaire à tout moment.

Pour s'en souvenir : l'entrepôt de la compagnie 🚛

🏬 Le compte de stockage

  • Compte de stockage = l'entrepôt de la compagnie, avec une adresse unique au monde (son nom)
  • Blob = la zone vrac : n'importe quelle marchandise, rangée par conteneur
  • Files = le classeur partagé du bureau, que tous les postes ouvrent comme un lecteur réseau
  • Queue = le tableau des bons de livraison à traiter dans l'ordre
  • Table = le registre simple : une ligne par camion, des colonnes libres

📦 La redondance

  • LRS = 3 copies du dossier dans le même bureau : un feu, et tout part
  • ZRS = 3 copies dans 3 bureaux de la même ville
  • GRS = en plus, une copie au terminal d'une autre province, qu'on n'ouvre qu'en cas de sinistre
  • RA- = on a le droit de consulter la copie de l'autre province à tout moment
  • GZRS = 3 bureaux en ville + l'autre province : le maximum

1 · Les 4 services et les 3 types de données

ServicePour quoiExemple
BlobDonnées non structurées en masse (texte, binaire), accès par URL/RESTImages d'un site, vidéos, sauvegardes, archives
FilesPartages réseau SMB / NFS montés par plusieurs VMRemplacer un serveur de fichiers, fichiers de config partagés
QueueMessages de 64 Ko max, des millions par fileImage envoyée → message → une fonction crée la miniature
TableNoSQL clé/attributs, sans schémaProfils, journaux simples (Cosmos DB Table API = version premium)

Les 3 catégories de données : de VM (disques managés = blobs de pages, partages Files), non structurées (Blob, Data Lake Storage) et structurées (Table, Cosmos DB, SQL Database). Accès par HTTP/HTTPS, SDK, PowerShell, CLI, portail ou Explorateur Stockage. ➕ Blob accepte aussi SFTP (il faut l'espace de noms hiérarchique) et NFSv3.

2 · Les types de comptes

TypeServicesRedondancePour
Standard usage général v2 (HDD)Blob, Files, Queue, TableLes 6 : LRS, ZRS, GRS, RA-GRS, GZRS, RA-GZRSPresque tout : le choix par défaut
Premium objets blob de blocs (SSD)Blob seulement (blocs et ajout)LRS, ZRSBeaucoup de transactions, petits objets, faible latence
Premium partages de fichiers (SSD)Files seulementLRS, ZRSPartages SMB et NFS haute performance
Premium blobs de pages (SSD)Blobs de pages seulementLRS seulementDisques de VM, bases de données
À retenir : on ne convertit pas Standard ↔ Premium : il faut créer un nouveau compte et copier. Un vieux compte v1 ou BlobStorage se met à niveau sur place vers v2. Tous les comptes sont chiffrés au repos (SSE). ➕ examen : le nom du compte fait 3 à 24 caractères, minuscules et chiffres seulement, et doit être unique dans tout Azure (c'est un morceau d'URL).

3 · La redondance (réplication)

Ce qui tombeQui survit
Un serveur dans le centre de donnéesToutes : LRS, ZRS, GRS, RA-GRS, GZRS, RA-GZRS
Le centre de données entierZRS, GRS, RA-GRS, GZRS, RA-GZRS (pas LRS)
Toute la régionGRS, RA-GRS, GZRS, RA-GZRS
Lire pendant la panne de régionRA-GRS, RA-GZRS seulement

Avec GRS (sans RA), la copie secondaire n'est lisible qu'après un basculement. Le module dit « initié par Microsoft » ; ➕ tu peux aussi lancer toi-même un basculement de compte. Durabilité GRS/GZRS : au moins 16 neuf (99,99999999999999 %) par an. ZRS n'existe pas dans toutes les régions. LRS convient si les données se recréent facilement ou doivent rester à un seul endroit (gouvernance).

4 · Les adresses (points de terminaison)

Un objet = adresse + chemin : https://moncompte.blob.core.windows.net/conteneur/photo.jpg. Domaine personnalisé (Blob) : un enregistrement CNAME images.optifuel.cloud → moncompte.blob.core.windows.net.

5 · Sécuriser l'accès réseau

🚧 Point de terminaison de service

  • Le compte garde son adresse publique
  • Le pare-feu du compte (Pare-feux et réseaux virtuels) n'accepte que certains sous-réseaux et certaines IP publiques
  • Le VNet doit être dans la même région (ou sa paire)
  • Simple et gratuit : bon pour le dev

🔒 Point de terminaison privé

  • Le compte reçoit une IP privée dans ton VNet
  • Le trafic reste sur le réseau Microsoft, jamais sur Internet
  • On peut ensuite désactiver l'accès public
  • ➕ Il faut une zone DNS privée privatelink.blob.core.windows.net (vu dans Azure DNS)
  • Recommandé pour la production

6 · ➕ En CLI

az storage account create -g rg-labo -n optifuelstock123 -l eastus \
  --sku Standard_ZRS --kind StorageV2 --min-tls-version TLS1_2
az storage account show -g rg-labo -n optifuelstock123 --query primaryEndpoints
az storage account update -g rg-labo -n optifuelstock123 --sku Standard_GZRS
az storage account network-rule add -g rg-labo --account-name optifuelstock123 \
  --vnet-name vnet --subnet app
az storage account update -g rg-labo -n optifuelstock123 --default-action Deny

Le SKU combine performance et redondance : Standard_LRS, Standard_GZRS, Premium_LRS… --default-action Deny = tout est refusé sauf les règles réseau ajoutées. Un compte vide ne coûte presque rien.

🚛 Appliquer à Optifuel

Les manifestes scannés d'Optifuel iraient ici.

  • Un compte Standard v2 en Canada Central, avec un conteneur manifestes pour les scans ACE/ASFC.
  • Redondance ZRS : les données restent au Canada et survivent à la perte d'un centre de données. GZRS si l'employeur veut une copie en Canada Est (la paire, donc toujours au pays).
  • Point de terminaison privé depuis le VNet du cluster, et accès public désactivé : les manifestes ne sont jamais exposés.
  • Tu as déjà noté « Azurite » pour le dev local : c'est l'émulateur de ce même compte de stockage, gratuit sur ton poste.

💡 Pour un recruteur : « données de douane au Canada, redondance zonale, aucun accès public » est une phrase qui parle.

Pièges d'examen

🪤« Je veux pouvoir lire mes données pendant une panne de toute la région : GRS. »GRS ne permet de lire qu'après un basculement. Il faut RA-GRS ou RA-GZRS.
🪤« Je passe mon compte Standard en Premium dans les paramètres. »Impossible : on crée un nouveau compte Premium et on copie les données.
🪤« Mon compte Premium de blobs de pages en GRS. »Premium blobs de pages = LRS seulement. Les autres Premium : LRS ou ZRS.
🪤« ZRS copie les données dans une autre région. »Non : 3 zones d'une même région. L'autre région, c'est GRS / GZRS.
🪤« Le nom de compte Optifuel_Stock est valide. »Seulement minuscules et chiffres, 3 à 24 caractères, unique dans Azure : optifuelstock.
🪤« Avec un point de terminaison de service, mon compte n'a plus d'adresse publique. »Il la garde (mais filtrée). L'IP privée, c'est le point de terminaison privé.

Mini-quiz

Encart Terraform

🟪 Compte de stockage + accès réseau limité

resource "azurerm_storage_account" "manifestes" {
  name                            = "optifuelstock123"   # 3-24, minuscules + chiffres
  resource_group_name             = azurerm_resource_group.labo.name
  location                        = "canadacentral"
  account_kind                    = "StorageV2"
  account_tier                    = "Standard"           # ou Premium
  account_replication_type        = "ZRS"                # LRS, GRS, RAGRS, GZRS, RAGZRS
  min_tls_version                 = "TLS1_2"
  public_network_access_enabled   = false                # accès par point de terminaison privé
  shared_access_key_enabled       = false                # Entra ID seulement
}
