Configurer Azure Container Instances

Conteneurs ou VM, Azure Container Instances, groupes de conteneurs, Azure Container Apps et le choix ACI / ACA / AKS. Les notions marquées ➕ examen complètent le module.

⏱ Lecture : 7 min · module complet 🎯 ACI vs Container Apps vs AKS : question fréquente
💡
À retenir : un conteneur partage le noyau de l'hôte : léger et rapide, mais moins isolé qu'une VM. ACI lance un conteneur en secondes, sans serveur (IP publique + DNS, Azure Files, Linux ou Windows). Un groupe de conteneurs partage IP, ports et volumes (≈ un pod). Container Apps = serverless qui grandit jusqu'à zéro ; AKS = Kubernetes complet.

Pour s'en souvenir : camion complet ou conteneur maritime 🚛

🚚 VM vs conteneur

  • VM = un camion complet avec son moteur (le noyau de l'OS) : lourd, long à démarrer, mais bien séparé des autres
  • Conteneur = un conteneur maritime standard : il n'a pas de moteur, il partage celui du porteur ; on en charge beaucoup sur un même châssis
  • Image = le plan de chargement : code, runtime, outils, bibliothèques, réglages

🏗️ Les 3 façons de le transporter

  • ACI = un taxi-remorque à la course : tu donnes le conteneur, il roule en quelques secondes, tu paies à la seconde
  • Container Apps = un transporteur géré : il ajoute ou retire des remorques selon les commandes, jusqu'à zéro
  • AKS = ta propre flotte avec ton répartiteur (Kubernetes) : tout le contrôle, tout le travail

3 · Les groupes de conteneurs

📐 Règles

  • Le groupe = la ressource de plus haut niveau d'ACI
  • Ressources du groupe = la somme des demandes de ses conteneurs (CPU, mémoire, GPU)
  • Partagent IP, ports et étiquette DNS
  • Pas de mappage de ports : deux conteneurs ne peuvent pas écouter le même port
  • Groupe supprimé = IP et FQDN libérés (pas garantis au retour)
  • ➕ Plusieurs conteneurs dans un groupe : Linux seulement

Usages : sidecar qui tire le contenu, collecteur de journaux, conteneur de surveillance, front-end + back-end.

5 · Le labo 09b en bref

  1. Déployer une instance de conteneur à partir d'une image Docker (ex. mcr.microsoft.com/azuredocs/aci-helloworld), avec une étiquette DNS.
  2. Tester : ouvrir le FQDN dans le navigateur et lire les journaux du conteneur.

6 · ➕ En CLI

az container create -g rg-labo -n hello --image mcr.microsoft.com/azuredocs/aci-helloworld \
  --os-type Linux --cpu 1 --memory 1.5 --ports 80 --dns-name-label hello-mah123 \
  --restart-policy Always -l eastus
az container show -g rg-labo -n hello --query "{fqdn:ipAddress.fqdn,etat:instanceView.state}" -o table
az container logs -g rg-labo -n hello
az container exec -g rg-labo -n hello --exec-command "/bin/sh"
az container create -g rg-labo --file groupe.yaml        # groupe multi-conteneurs
az containerapp up -n optiapp -g rg-labo --image monregistre.azurecr.io/optifuel:1.0 \
  --ingress external --target-port 3000                  # Container Apps

🚛 Appliquer à Optifuel

Optifuel est déjà en conteneurs, donc :

  • ACI avec --restart-policy Never : lancer une tâche ponctuelle (import de données, script de maintenance) sans cluster.
  • Container Apps : l'image Next.js roule avec mise à l'échelle jusqu'à zéro, sans gérer de nœuds (option économique pour une démo).
  • Ta prod k3s ressemble à AKS : tu gardes le contrôle total, c'est aussi ce que vise la CKA.

Pièges d'examen

🪤« Les conteneurs isolent aussi bien que les VM. »Isolement léger : pour une vraie frontière de sécurité entre clients, des VM.
🪤« Mon ACI dans un réseau virtuel garde son IP publique. »Dans un VNet : pas d'IP publique, accès privé seulement.
🪤« Deux conteneurs du groupe écoutent le port 80. »Ils partagent l'espace de ports : pas de mappage, ports différents obligatoires.
🪤« Groupe multi-conteneurs Windows. »➕ Les groupes à plusieurs conteneurs sont Linux seulement.
🪤« Mon script ACI recommence en boucle après avoir fini. »Stratégie par défaut Always. Pour une tâche unique : Never (ou OnFailure).
🪤« Pour une appli qui doit tomber à zéro la nuit, je prends ACI. »ACI ne se met pas à l'échelle. Container Apps descend à zéro.
🪤« Avec Container Apps, je lance mes commandes kubectl. »Container Apps n'expose pas l'API Kubernetes. Pour ça : AKS.
🪤« Je supprime et recrée le groupe : il garde son IP. »Suppression = IP et FQDN libérés.

🟪 Groupe de conteneurs ACI

resource "azurerm_container_group" "hello" {
  name                = "hello"
  resource_group_name = azurerm_resource_group.labo.name
  location            = "eastus"
  os_type             = "Linux"
  ip_address_type     = "Public"
  dns_name_label      = "hello-mah123"
  restart_policy      = "Always"     # OnFailure, Never
  container {
    name   = "web"
    image  = "mcr.microsoft.com/azuredocs/aci-helloworld:latest"
    cpu    = 1
    memory = 1.5
    ports {
      port     = 80
      protocol = "TCP"
    }
  }
}
