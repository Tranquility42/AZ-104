Créer, configurer et gérer des identités

Utilisateurs, groupes, appareils et licences dans Entra ID : qui entre, avec quel badge, sur quel appareil et avec quels outils payés.

⏱ Lecture : 12 min · module complet (14 unités) 🎯 Domaine examen : Identités et gouvernance (20-25 %)
💡
À retenir : il y a 3 sortes d'utilisateurs (cloud, synchronisés, invités), 2 types de groupes (sécurité, Microsoft 365) et 3 façons d'en être membre (attribué, dynamique utilisateur, dynamique appareil). Un appareil peut être inscrit, joint ou joint hybride. On donne les licences par groupe, ce qui demande P1 et un emplacement d'utilisation. Un utilisateur supprimé reste 30 jours dans la corbeille.

1 · Les utilisateurs

Identité cloud

☁️ Créée dans Entra

  • Existe seulement dans Entra ID
  • Comptes admin, utilisateurs gérés dans le cloud
  • Source : Microsoft Entra ID ou annuaire externe
Identité synchronisée

🔄 Venue de l'AD local

  • Source : Windows Server AD
  • Outil recommandé : Entra Cloud Sync (agent léger, plusieurs forêts)
  • Entra Connect Sync pour les cas complexes : synchro d'appareils, groupes de plus de 50 000 membres
Invité (B2B)

🧳 Hors organisation

  • Compte Microsoft ou d'un autre fournisseur
  • Source : Utilisateur invité
  • Type d'utilisateur : Invité (les autres sont Membre)
  • À supprimer à la fin du travail

🗑️ Supprimer et restaurer

Jour 0 : suppression
L'utilisateur part dans Utilisateurs supprimés, avec toutes ses propriétés.
Jours 1 à 30 : restaurable
Utilisateurs supprimés → sélectionner → Restaurer l'utilisateur.
Après 30 jours : définitif
Suppression automatique. Plus aucune restauration possible.

Rôles qui peuvent restaurer ou supprimer définitivement : Administrateur général, Administrateur d'utilisateurs, Support partenaire niveau 1 et niveau 2. Astuce : cocher plusieurs utilisateurs dans la liste permet d'agir sur plusieurs à la fois.

2 · Les groupes

🔐 Groupe de sécurité

  • But : donner l'accès aux ressources
  • Membres : utilisateurs, appareils, principaux de service
  • Créé par un administrateur Entra

💬 Groupe Microsoft 365

  • But : collaborer (boîte aux lettres, calendrier, fichiers, site SharePoint partagés)
  • Peut inclure des personnes externes
  • Créable par les utilisateurs et les admins

Types d'appartenance × type de groupe

AppartenanceCommentSécuritéMicrosoft 365
Attribuée (Assigned)Ajout et retrait à la main✓✓
Utilisateur dynamiqueRègle sur les attributs (service, poste, lieu)✓✓
Appareil dynamiqueRègle sur les attributs de l'appareil✓✗
💳 Les groupes dynamiques demandent Entra ID P1 (ou Intune pour l'Éducation pour les règles d'appareils). La règle est réévaluée dès qu'un attribut change. Exemple : user.department -eq "Marketing".

3 · Les appareils

Entra inscrit (registered)

📱 Ton téléphone perso

L'appli de la compagnie sur ton cellulaire : tu ouvres la session avec ton compte à toi.
  • BYOD, mobiles · appartient à l'utilisateur ou à l'organisation
  • Connexion avec un compte local (mot de passe, Hello, NIP, biométrie)
  • Windows 10+, macOS, iOS, Android, Linux (Ubuntu, RHEL)
  • Gestion : MDM/MAM (Intune). SSO cloud, accès conditionnel
Entra joint (joined)

🚚 Le camion de la compagnie

Il appartient à la compagnie et tu démarres avec la clé de la compagnie (ton compte pro).
  • Organisations cloud d'abord · appartient à l'organisation
  • Connexion avec un compte professionnel Entra
  • Windows 10/11 (pas Famille), VM Windows Server 2019+ dans Azure (pas Server Core)
  • Joint par OOBE, inscription en bloc ou Autopilot
  • SSO cloud et local, SSPR, réinitialisation du NIP Hello
Entra joint hybride

🏭 Le camion du siège, aussi enregistré dans le cloud

Immatriculé au siège (AD local) et connu du bureau de répartition cloud.
  • Organisations hybrides avec un AD local
  • Joint à l'AD local + enregistré dans Entra ID
  • Windows 10/11, Windows Server 2016/2019/2022
  • Gestion : GPO, Configuration Manager, cogestion Intune
  • Pour les applis Win32 qui ont besoin de l'authentification machine AD

ℹ️ L'écriture différée des appareils (device writeback) n'est plus prise en charge. Elle est remplacée par cloud Kerberos Trust, qui donne aux appareils joints l'accès aux ressources locales.

4 · Les licences

👥 Licences par groupe

  • On attribue une licence à un groupe de sécurité (cloud, synchronisé ou dynamique). Les membres l'obtiennent, et ceux qui sortent la perdent
  • Prérequis : Entra ID P1, ou Office 365 E3 et plus
  • 1 licence par membre unique : 1 000 membres = 1 000 licences
  • Même licence reçue par 2 groupes, ou en direct + groupe : consommée une seule fois
  • On peut désactiver des plans de service (ex. Viva Engage)
  • Se gère dans le Centre d'administration Microsoft 365 : Facturation → Licences

🌍 L'emplacement d'utilisation

Il est obligatoire pour recevoir une licence, parce que certains services ne sont pas offerts dans tous les pays. Sans valeur, l'utilisateur hérite de l'emplacement de l'annuaire. Bonne pratique : le remplir dès la création du compte.

Migrer du direct vers les groupes : créer le groupe, y attribuer la licence, vérifier (aucune erreur, licence « héritée »), puis seulement retirer les licences directes. Sinon l'utilisateur garderait sa licence en quittant le groupe.

Les erreurs d'attribution (et leur nom PowerShell)

ErreurCodeSolution
Licences insuffisantesCountViolationAcheter ou libérer des licences
Plans de service en conflitMutuallyExclusiveViolationEx. E1 direct + E3 de groupe. L'admin désactive un plan ou retire la licence en double (rien n'est automatique)
Un autre produit dépend de cette licenceDependencyViolationGarder le plan requis autrement, ou désactiver le service dépendant
Emplacement d'utilisation non autoriséProhibitedInUsageLocationViolationRemplir l'emplacement dans le profil, ou retirer l'utilisateur du groupe
Adresse proxy en double—Corriger l'adresse dans Exchange, puis Retraiter

Les erreurs sont notées sur l'utilisateur, pas affichées tout de suite. Après correction, bouton Retraiter (groupe ou utilisateur → Licences). Les modules complémentaires exigent leur produit prérequis dans le même groupe. Pour supprimer un groupe sous licence, il faut d'abord retirer ses licences.

5 · Attributs de sécurité personnalisés

Des étiquettes clé-valeur propres à l'entreprise, posées sur des utilisateurs ou des applications d'entreprise. Exemples : Projet = Optifuel, TauxHoraire = 32. Elles servent à classer, à restreindre qui voit l'info, et à contrôler l'accès à des ressources Azure (ex. les blobs d'un projet).

  • Types : booléen, entier, chaîne ; valeur unique ou multiple ; valeurs libres ou prédéfinies
  • Disponibles dans tous les locataires, y compris pour les utilisateurs synchronisés
  • Non pris en charge par Entra Domain Services ni dans les jetons SAML et JWT

Pièges d'examen

🪤« Je crée un groupe Microsoft 365 avec appartenance appareil dynamique. »Impossible. Appareil dynamique = groupe de sécurité seulement.
🪤« Les groupes dynamiques sont inclus dans Entra ID Free. »Non. Il faut P1.
🪤« J'ai supprimé un utilisateur il y a 45 jours, je le restaure. »Trop tard. Au-delà de 30 jours, la suppression est définitive.
🪤« La licence de groupe échoue pour un utilisateur, la cause doit être le nombre de licences. »Pas forcément. Vérifie d'abord l'emplacement d'utilisation : sans lui, aucune licence ne peut être attribuée.
🪤« Un PC Windows 11 Famille peut être joint à Entra. »Non. Joint = Windows 10/11 sauf Famille. Un appareil perso sera plutôt inscrit (registered).
🪤« L'entreprise garde ses GPO et ses applis Win32 liées à AD, donc je choisis Entra joint. »Non. Il faut Entra joint hybride.
🪤« Un utilisateur dans 2 groupes avec la licence E3 consomme 2 licences. »Faux. Une même licence n'est consommée qu'une fois.

Mini-quiz

Encart Terraform

🟪 Utilisateur, invité et groupe dynamique avec azuread

Le provider azuread gère utilisateurs, invités et groupes. Les licences ne s'y gèrent pas : elles passent par le Centre d'administration Microsoft 365 ou Microsoft Graph (Set-MgUserLicense).

resource "azuread_user" "dominique" {
  user_principal_name = "DominiqueK@contoso.onmicrosoft.com"
  display_name        = "Dominique Koch"
  department          = "Transport"
  usage_location      = "CA"   # obligatoire avant une licence
  password            = var.initial_password
}

# Invité (B2B) : un sous-traitant
resource "azuread_invitation" "soustraitant" {
  user_email_address = "owner.op@gmail.com"
  redirect_url       = "https://myapps.microsoft.com"
}

# Groupe de sécurité dynamique (demande P1)
resource "azuread_group" "transport" {
  display_name     = "Chauffeurs Transport"
  security_enabled = true
  types            = ["DynamicMembership"]

  dynamic_membership {
    enabled = true
    rule    = "user.department -eq \"Transport\""
  }
}
