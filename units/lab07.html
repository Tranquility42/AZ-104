Plan du labo 07 · Gérer le stockage Azure

Le résultat final à construire, avec tous les réglages, sans les étapes. Regarde le plan, construis tout toi-même (portail, CLI ou Terraform), puis vérifie avec les résultats attendus. Durée prévue : environ 50 minutes.

🧩 Mode « plan d'architecte » Énoncé officiel si tu bloques
💡
Le scénario : l'entreprise veut déplacer des fichiers rarement consultés vers un stockage moins cher et bien protégé. Tu construis un compte de stockage verrouillé : rien de public, un conteneur immuable, un accès ponctuel par SAS, un partage de fichiers, puis tu fermes l'accès à tout sauf un VNet.

À savoir avant de commencer

⚠️ Différences avec ton image

  • Ton image vient d'une ancienne version du labo : elle avait une VM az104-07-vm0 (réseau 10.70.0.0/22). La version actuelle n'a pas de VM ni de modèle à déployer
  • Les noms ont changé : az104-rg7 (un seul groupe), conteneur data, partage share1, VNet vnet1
  • La phase « navigateur privé » (Task 4 de ton image) = les tests de l'URL avec et sans SAS

🧠 Les pièges du labo

  • Si ton IP n'est pas dans le pare-feu, le portail lui-même ne peut plus lire le conteneur
  • Si tu ne peux pas signer la SAS avec la clé du compte, c'est normal : utilise la délégation d'utilisateur. Il te faut le rôle Blob Data Contributor
  • L'immuabilité de 180 jours empêche de supprimer le fichier. Au nettoyage, si Azure refuse de supprimer le groupe, supprime d'abord la stratégie d'immuabilité (possible tant qu'elle n'est pas verrouillée), puis le groupe. Ne la verrouille jamais dans un labo
  • Les changements réseau prennent quelques minutes
  • 💸 Rien de cher ici (pas de VM) : quelques sous

Les notions derrière ce labo : comptes de stockage · Stockage Blob · sécurité · Azure Files.
