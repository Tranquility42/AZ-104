Présentation des machines virtuelles Azure

Checklist avant de créer une VM, tailles, disques, facturation, outils de création, disponibilité et sauvegarde. Les notions marquées ➕ examen complètent le module.

⏱ Lecture : 9 min · module complet 🎯 Désallouer vs arrêter, disques OS, 15 caractères : questions fréquentes
💡
À retenir : une VM = calcul + disques + carte réseau + réseau virtuel + NSG + IP. Planifie le réseau d'abord. Le calcul est facturé à la minute et s'arrête seulement si la VM est désallouée ; le stockage reste facturé. Disque OS : pas Ultra ni Premium SSD v2. Site Recovery = basculer ailleurs, Backup = revenir en arrière.

Pour s'en souvenir : louer un camion chez Azure 🚛

🚚 La location

  • VM = un camion loué : tu choisis le modèle, tu conduis, tu fais l'entretien de la cabine (l'OS)
  • Taille = la classe du camion (porteur, tracteur, frigo…) : plus gros = plus cher
  • Disque OS = le moteur ; disque de données = la remorque qu'on peut détacher et atteler à un autre camion
  • Disque temporaire = le coffre de la cabine : vidé quand le camion change de garage

💵 La facture

  • Calcul = la location à la minute du camion
  • Arrêter et désallouer = rendre les clés : plus de location, mais tu paies encore le stationnement (le stockage)
  • Arrêter depuis l'OS = couper le moteur sur le terrain : le camion reste réservé et facturé
  • Instance réservée = location longue durée 1 ou 3 ans : jusqu'à −72 %

1 · La checklist avant de créer une VM

ÉlémentCe qu'il faut savoir
RéseauÀ planifier avant : plages et sous-réseaux difficiles à changer après. Pas de chevauchement entre réseaux reliés.
Nom15 caractères max pour Windows, 64 pour Linux. Le nom devient aussi le nom de l'ordinateur. Convention : deveus-webvm01 (environnement, région, rôle, numéro).
RégionProche des utilisateurs, conformité, prix différents selon la région, et toutes les tailles ne sont pas partout (ton erreur SkuNotAvailable !).
TailleCalcul + mémoire + stockage. Choisie selon la charge (tableau ci-dessous).
DisquesOS + temporaire d'office ; ajouter des disques de données. Nombre max ≈ 2 par vCPU.
OSImage Marketplace, image personnalisée ou Azure Compute Gallery (partager et répliquer des images entre régions).

Bon réflexe : mettre les données sur un disque séparé de l'OS. Si la VM meurt, on détache le disque et on l'attache à une nouvelle VM. Le disque temporaire n'est pas facturé, mais son contenu peut disparaître (➕ ne jamais y mettre de données importantes).

4 · Ce qui est facturé

💵 Facturé

  • Calcul : tarif horaire, facturé à la minute (55 min = 55 min)
  • Stockage (disques managés) : facturé même VM arrêtée
  • IP publique
  • Licence OS incluse pour Windows (selon les cœurs) → Linux coûte moins cher. Azure Hybrid Benefit réutilise tes licences.

🆓 Gratuit

  • Carte réseau (nombre limité par la taille)
  • NSG
  • Disque temporaire
  • Le VMSS lui-même (tu paies ses VM)
Mode de paiementEngagementRabaisPour
Paiement à l'utilisationAucun—Tests, charges imprévisibles, courte durée

az vm create -g rg-labo -n web01 --image Ubuntu2204 --size Standard_B1s \
  --admin-username azureuser --generate-ssh-keys -l eastus
az vm list-sizes -l eastus -o table          # tailles d'une région
az vm list-skus -l eastus --size Standard_B --all -o table   # ➕ voir les restrictions
az vm resize -g rg-labo -n web01 --size Standard_B2s
az vm deallocate -g rg-labo -n web01         # arrête la facture de calcul
az vm auto-shutdown -g rg-labo -n web01 --time 2300

6 · Disponibilité, reprise et sauvegarde

ServiceProtège contreEn clair
Zones de disponibilitéLa perte d'un centre de données3 zones par région, chacune avec son courant, son réseau et sa climatisation
VMSSSurcharge, panne d'une VMGroupe de VM identiques qui grandit tout seul (page suivante)
Load BalancerUne VM qui tombeRépartit le trafic entre plusieurs VM
Redondance du stockagePanne matérielle ou régionaleLRS, ZRS, GRS… (voir comptes de stockage)
Azure Site RecoveryLa perte d'une région ou d'un siteRéplique les VM vers une autre région, bascule (failover), puis retour (failback). Tests sans toucher la prod.
Azure BackupSuppression, corruption, rançongicielCopies restaurables dans un coffre Recovery Services, selon une stratégie (quand + combien de temps)
Site Recovery ≠ Backup. Site Recovery garde une copie qui roule pour redémarrer ailleurs vite (le camion de relève). Backup garde des photos datées pour revenir en arrière (l'historique des bons de livraison). Azure Backup : transfert de données non facturé, rétention longue, sauvegardes cohérentes avec les applis (VSS sous Windows), stockage LRS ou GRS. Composants : agent MARS, DPM, Azure Backup Server, extension de VM.

🚛 Appliquer à Optifuel

Si un jour Optifuel tourne sur une VM Azure :

  • Nœud k3s = VM Linux série B (pas de licence Windows à payer).
  • PostgreSQL sur un disque de données séparé (Premium ou Standard SSD), pas sur le disque OS.
  • VM de dev : arrêt automatique le soir et az vm deallocate.
  • Prod toujours allumée : instance réservée 1 an et Azure Backup sur la VM.

Pièges d'examen

🪤« J'ai arrêté la VM depuis Windows, je ne paie plus rien. »Arrêt depuis l'OS = toujours alloué, calcul facturé. Il faut arrêter et désallouer (portail ou az vm deallocate). Et le stockage reste facturé dans tous les cas.
🪤« Je mets le disque OS sur un Ultra Disk pour la vitesse. »Ultra et Premium SSD v2 ne peuvent pas être disques OS.
🪤« Je nomme ma VM Windows « optifuel-prod-web-01 ». »15 caractères max pour Windows (64 pour Linux).
🪤« La taille voulue n'apparaît pas : elle n'existe pas. »VM allumée = seulement les tailles du cluster actuel. Désalloue, puis redimensionne. Sinon, elle n'existe pas dans la région.
🪤« Le disque temporaire est sauvegardé avec la VM. »Le disque temporaire peut être vidé (redimensionnement, maintenance). Données importantes = disque de données.
🪤« Azure Site Recovery sert à restaurer un fichier supprimé hier. »Ça, c'est Azure Backup. Site Recovery = basculer toute la VM dans une autre région.
🪤« La carte réseau et le NSG font monter la facture. »Les deux sont gratuits. L'IP publique, elle, est facturée.
