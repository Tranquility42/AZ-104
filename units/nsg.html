Groupes de sécurité réseau (NSG)

Les règles qui laissent passer ou bloquent le trafic vers tes VM, au niveau du sous-réseau et de la carte réseau. Plus les groupes de sécurité d'application (ASG) pour écrire ces règles par rôle plutôt que par adresse IP.

⏱ Lecture : 8 min · module complet 🎯 Questions de calcul très fréquentes (priorités, ordre)
💡
À retenir : un NSG est une liste de règles Autoriser / Refuser lues par priorité (100 à 4096, le plus petit chiffre passe en premier). Dès qu'une règle correspond, Azure arrête de lire. On l'attache à un sous-réseau et/ou à une carte réseau : le trafic doit être autorisé aux deux niveaux.

Pour s'en souvenir : les guérites du terminal 🚛

🚧 Les barrières

  • NSG sur le sous-réseau = la guérite à l'entrée de la zone (quais, atelier) : elle filtre pour tous les camions de la zone
  • NSG sur la carte réseau = le cadenas sur la porte d'un camion précis
  • Pour livrer, il faut passer la guérite ET le cadenas. Un seul refus et c'est non
  • En entrant, on passe la guérite d'abord, puis le cadenas. En sortant, l'inverse

📋 La liste du gardien

  • Règles = la liste du gardien, lue de haut en bas (priorité 100 avant 200)
  • Dès qu'une ligne correspond au camion, le gardien applique et arrête de lire
  • Règles par défaut = les consignes imprimées en bas de la liste (65000+), qu'on ne peut pas effacer, seulement passer devant
  • ASG = un macaron « citerne » ou « frigo » : la règle dit « les citernes vont au quai 3 », peu importe la plaque
  • Balise de service = un macaron fourni par Microsoft : « Internet », « VirtualNetwork », « Storage »

1 · Où attacher un NSG

➡️ Entrant

NSG du sous-réseau d'abord, puis NSG de la carte réseau.

⬅️ Sortant

NSG de la carte réseau d'abord, puis NSG du sous-réseau.

La règle d'or : si un NSG existe à un niveau, il faut une règle Autoriser à ce niveau. Sous-réseau autorise le port 80 mais NIC ne dit rien ? Bloqué par le DenyAllInbound de la NIC. Sans aucun NSG, tout passe. Les NSG filtrent aussi le trafic entre VM du même sous-réseau.

2 · Anatomie d'une règle

ChampValeurs possibles
SourceTous, adresses IP, Mon adresse IP, balise de service, ASG
Plage de ports sourcePresque toujours * (le port source est aléatoire)
DestinationTous, adresses IP, balise de service, ASG
Service / port de destinationPrédéfini (RDP 3389, SSH 22, HTTP 80, HTTPS 443) ou plage perso
ProtocoleTCP, UDP, ICMP, Tous (ESP et AH seulement en JSON/PowerShell)
ActionAutoriser ou Refuser
Priorité100 à 4096, unique dans le NSG. Plus petit = lu en premier. Laisse des trous (100, 200, 300) pour insérer plus tard

Règles augmentées : une seule règle peut viser plusieurs IP et plusieurs ports (ex. 80,443,8080,8090) au lieu de quatre règles.

➕ examen : les 6 règles par défaut (impossibles à supprimer)

SensNomPrioritéSource → DestinationAction
EntrantAllowVNetInBound65000VirtualNetwork → VirtualNetworkAutoriser
EntrantAllowAzureLoadBalancerInBound65001AzureLoadBalancer → TousAutoriser
EntrantDenyAllInBound65500Tous → TousRefuser
SortantAllowVNetOutBound65000VirtualNetwork → VirtualNetworkAutoriser
SortantAllowInternetOutBound65001Tous → InternetAutoriser
SortantDenyAllOutBound65500Tous → TousRefuser

En résumé : entrant, seul le VNet et l'équilibreur de charge Azure passent, Internet est bloqué. Sortant, la VM peut aller vers le VNet et Internet. Pour changer ça, crée une règle avec une priorité plus petite (ex. 100).

🧠 Réponses

  • RDP (3389) depuis ton IP ? Bloqué. La règle 100 correspond en premier, Azure arrête de lire. La 200 ne sert à rien
  • Correction : donner à l'autorisation une priorité plus petite que le refus (ex. 90, ou passer le refus à 300)
  • HTTP (80) depuis Internet ? Autorisé par la 300… si le NSG du sous-réseau l'autorise aussi
  • SSH (22) ? Aucune règle perso, donc bloqué par DenyAllInBound

🔍 Pour vérifier : Règles de sécurité effectives sur la VM, la carte réseau ou le sous-réseau (fusionne tous les NSG). Network Watcher › Vérification du flux IP te dit quelle règle bloque un paquet précis.

4 · Groupes de sécurité d'application (ASG)

🏷️ Le principe

On colle un macaron sur la carte réseau de chaque VM (asg-web, asg-app), puis les règles NSG utilisent ces macarons comme source ou destination. Plus besoin de connaître les IP.

  1. Créer un ASG par rôle : asg-web, asg-app
  2. Associer la carte réseau de chaque VM à son ASG
  3. Écrire les règles NSG avec les ASG

🛒 L'exemple du détaillant en ligne

Prio.De → VersPortAction
100Internet → asg-web80, 443Autoriser
110asg-web → asg-app1433 (SQL)Autoriser
120Tous → asg-app80, 443Refuser

Tu ajoutes une 5e VM web ? Associe-la à asg-web, elle hérite des règles sans rien toucher.

ASG

Groupe de tes VM, que tu crées. Doit être dans le même VNet que les cartes réseau.

Balise de service

Groupe d'IP Microsoft tenu à jour par Azure : Internet, VirtualNetwork, AzureLoadBalancer, Storage, Sql…

Adresse IP

Une IP ou une plage CIDR précise. À éviter quand un ASG ou une balise fait l'affaire.

5 · Pour ton exercice (refait sans les instructions)

  1. Recrée app-vnet (10.1.0.0/16) avec frontend 10.1.0.0/24 et backend 10.1.1.0/24. Supprime le sous-réseau « default » ou renomme-le
  2. Crée l'ASG app-frontend-asg dans la même région
  3. Crée le NSG app-vnet-nsg et associe-le au sous-réseau backend (NSG › Sous-réseaux › Associer)
  4. Règle entrante : source ASG app-frontend-asg, destination tous, port 22 (SSH), Autoriser, priorité 100
  5. Associe la carte réseau de VM1 à app-frontend-asg (VM › Réseau › Groupes de sécurité d'application)

💸 VNet, NSG et ASG sont gratuits. Seules les VM coûtent : prends une petite taille (B1s) et supprime le groupe de ressources à la fin. Les zones DNS (optionnelles) coûtent quelques sous par mois.

Pièges d'examen

🪤« Priorité 4000 passe avant priorité 200, c'est le plus gros chiffre qui gagne. »Inverse. Le plus petit chiffre est lu en premier.
🪤« J'ai un Refuser en 100 et un Autoriser en 200 sur le même port : la plus permissive l'emporte. »Non, la première qui correspond gagne : Refuser.
🪤« Le NSG du sous-réseau autorise le port 80, donc ma VM est joignable. »Seulement si le NSG de la carte réseau (s'il existe) l'autorise aussi.
🪤« Je mets deux NSG sur le même sous-réseau. »Un seul par sous-réseau et un seul par carte réseau. Mais un même NSG peut servir à plusieurs sous-réseaux et cartes.
🪤« Je supprime DenyAllInBound pour tout ouvrir. »Les règles par défaut ne se suppriment pas. On les contourne avec une priorité plus petite.
🪤« J'ai autorisé le port 80 en entrée, il faut aussi une règle sortante pour la réponse. »Non : ➕ examen, les NSG sont avec état (stateful). La réponse repart automatiquement.
🪤« Les VM d'un même sous-réseau se parlent toujours, le NSG ne s'applique pas entre elles. »Faux, le NSG du sous-réseau filtre aussi ce trafic interne (même si AllowVNetInBound l'autorise par défaut).

Mini-quiz

Encart Terraform

🟪 NSG + ASG de l'exercice

resource "azurerm_application_security_group" "frontend" {
  name                = "app-frontend-asg"
  location            = "canadacentral"
  resource_group_name = azurerm_resource_group.labo.name
}

resource "azurerm_network_security_group" "app" {
  name                = "app-vnet-nsg"
  location            = "canadacentral"
  resource_group_name = azurerm_resource_group.labo.name

  security_rule {
    name                                  = "AllowSSHFromFrontend"
    priority                              = 100
    direction                             = "Inbound"
    access                                = "Allow"
    protocol                              = "Tcp"
    source_port_range                     = "*"
    destination_port_range                = "22"
    source_application_security_group_ids = [azurerm_application_security_group.frontend.id]
    destination_address_prefix           = "*"
  }
}

# Associer le NSG au sous-réseau backend
resource "azurerm_subnet_network_security_group_association" "backend" {
  subnet_id                 = azurerm_subnet.backend.id
  network_security_group_id = azurerm_network_security_group.app.id
}

# Mettre la carte réseau de VM1 dans l'ASG
resource "azurerm_network_interface_application_security_group_association" "vm1" {
  network_interface_id          = azurerm_network_interface.vm1.id
  application_security_group_id = azurerm_application_security_group.frontend.id
}
