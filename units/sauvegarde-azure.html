Sauvegarde Azure : présentation et protection des VM

Ce que protège Sauvegarde Azure, coffres, niveaux instantané/coffre/archive, cohérence, stratégies, sécurité du coffre et restauration d'une VM. Deux modules réunis. Les notions marquées ➕ examen complètent les modules.

⏱ Lecture : 9 min · 2 modules 🎯 Coffres, MARS, stratégies, options de restauration : questions fréquentes
💡
À retenir : Sauvegarde Azure range des copies datées dans un coffre (Recovery Services pour les VM). Une stratégie fixe la fréquence (Standard 1/jour, Enhanced toutes les 4 h min) et la rétention. L'instantané reste jusqu'à 5 jours (restauration rapide), puis la copie part au coffre. Suppression réversible 14 jours. RPO = perte acceptable, RTO = arrêt acceptable.

Pour s'en souvenir : le coffre-fort du terminal 🚛

🗄️ Le principe

  • Coffre (vault) = le coffre-fort du bureau où on range les copies des bons de livraison, à part des camions
  • Stratégie de sauvegarde = la consigne : faire une copie tous les soirs à 23 h et la garder 180 jours
  • Point de récupération = une copie datée dans le coffre
  • Suppression réversible = la copie jetée reste dans la poubelle verrouillée 14 jours

⏱️ RPO et RTO

  • RPO = combien de livraisons tu acceptes de perdre : sauvegarde toutes les heures → au pire 1 h de données perdues
  • RTO = combien de temps le camion peut rester au garage avant de reprendre la route : RTO 4 h → service rétabli en 4 h max
  • Backup = revenir en arrière ; Site Recovery = repartir ailleurs (voir la page Machines virtuelles)

3 · Stratégie de sauvegarde, coffre et sécurité

📅 Stratégie (policy)

  • Standard : 1 sauvegarde par jour (ou par semaine). Par défaut dans le portail : DailyPolicy, chaque jour à 12 h UTC, gardée 180 jours
  • Enhanced (améliorée) : toutes les 4, 6, 8, 12 ou 24 h (minimum 4 h, pas 1 h), choix des disques de données à sauvegarder
  • Rétention courte (jours) et longue (semaines, mois, années) ; niveau archive pour la conformité
  • Sauvegarder maintenant (à la demande) : rétention choisie à part, la stratégie ne s'applique pas

🔐 Protection du coffre

  • Suppression réversible : sauvegardes supprimées gardées 14 jours gratuits (réglable 14 à 180)
  • Immuabilité, autorisation multi-utilisateurs (MUA) contre un admin malveillant ou un rançongiciel
  • RBAC sur le coffre ; chiffrement par clés Microsoft ou clés client (Key Vault)
  • Trafic sur le réseau Azure : pas besoin d'Internet pour sauvegarder une VM
  • Redondance du coffre : LRS, ZRS, GRS (recommandée ; permet la restauration inter-régions). ➕ À choisir avant la 1re sauvegarde. L'archive n'existe pas en ZRS

Tout se pilote depuis Résilience (ancien Centre de sauvegarde) : travaux, coffres, abonnements, régions. Backup Explorer = un classeur Azure Monitor pour la vue d'ensemble ; journaux vers Log Analytics.

Suivi : coffre → Travaux de sauvegarde. Le plus rapide : un point encore dans le niveau instantané (restauration instantanée).

5 · Les exercices du module en bref

  1. Créer 2 VM (Windows NW-APP01, Linux NW-RHEL01) dans le groupe vmbackups, West US 2.
  2. Portail : VM Linux → Sauvegarde → coffre et DailyPolicy par défaut → Activer → Sauvegarder maintenant.
  3. CLI : créer le coffre azure-backup, protéger la VM Windows, lancer une sauvegarde.
  4. Restaurer NW-APP01 : compte de stockage intermédiaire, arrêter la VM, Remplacer l'existant.

6 · En CLI

az backup vault create -g vmbackups -n azure-backup -l westus2
az backup vault backup-properties set -g vmbackups -n azure-backup --backup-storage-redundancy GeoRedundant   # ➕ avant la 1re sauvegarde
az backup protection enable-for-vm -g vmbackups --vault-name azure-backup --vm NW-APP01 --policy-name EnhancedPolicy
az backup protection backup-now -g vmbackups --vault-name azure-backup \
  --container-name NW-APP01 --item-name NW-APP01 --retain-until 18-10-2030 --backup-management-type AzureIaasVM
az backup job list -g vmbackups --vault-name azure-backup -o table
az backup recoverypoint list -g vmbackups --vault-name azure-backup -c NW-APP01 -i NW-APP01 \
  --backup-management-type AzureIaasVM -o table      # ➕ points de restauration

🚛 Appliquer à Optifuel

Pour la base d'Optifuel :

  • PostgreSQL dans une VM Linux : sauvegarde de VM + scripts pré/post (ex. pg_dump ou figer les écritures) pour une copie cohérente avec l'appli.
  • Si un jour c'est Azure Database for PostgreSQL : protégé par un Backup vault, rétention longue pour les dossiers de conformité.
  • Fixe d'abord ton RPO : perdre au plus 1 journée de pleins saisis ? Alors une sauvegarde par jour suffit.

Pièges d'examen

🪤« Je sauvegarde une VM d'East US dans mon coffre de Canada Central. »➕ Le coffre Recovery Services doit être dans la même région que la VM.
🪤« J'installe l'agent MARS sur ma VM Linux. »MARS = Windows seulement (fichiers, dossiers, état système). Linux : sauvegarde de VM complète.
🪤« Ma stratégie Enhanced sauvegarde toutes les heures. »Minimum 4 h (4, 6, 8, 12, 24 h).
🪤« Je restaure en « Remplacer l'existant » avec la VM allumée. »Il faut arrêter la VM et fournir un compte de stockage intermédiaire.
🪤« Pour un seul fichier supprimé, je restaure toute la VM. »➕ Récupération de fichiers : un script monte le point de restauration, tu copies le fichier.
🪤« Backup et Site Recovery, c'est pareil. »Backup = revenir en arrière (copies datées). Site Recovery = basculer dans une autre région (réplication continue).
🪤« Une sauvegarde supprimée est perdue tout de suite. »Suppression réversible : gardée 14 jours par défaut.
🪤« Je change la redondance du coffre de LRS à GRS après des mois. »➕ À choisir avant de protéger la première ressource.

Mini-quiz

Encart Terraform

🟪 Coffre Recovery Services + sauvegarde d'une VM

resource "azurerm_recovery_services_vault" "coffre" {
  name                = "azure-backup"
  resource_group_name = azurerm_resource_group.labo.name
  location            = "eastus"             # même région que la VM
  sku                 = "Standard"
  storage_mode_type   = "GeoRedundant"
  soft_delete_enabled = true
}
resource "azurerm_backup_policy_vm" "quotidienne" {
  name                = "quotidienne-23h"
  resource_group_name = azurerm_resource_group.labo.name
  recovery_vault_name = azurerm_recovery_services_vault.coffre.name
  instant_restore_retention_days = 2
  backup {
    frequency = "Daily"
    time      = "23:00"
  }
  retention_daily {
    count = 30
  }
}
resource "azurerm_backup_protected_vm" "web" {
  resource_group_name = azurerm_resource_group.labo.name
  recovery_vault_name = azurerm_recovery_services_vault.coffre.name
  source_vm_id        = azurerm_linux_virtual_machine.web.id
  backup_policy_id    = azurerm_backup_policy_vm.quotidienne.id
}
