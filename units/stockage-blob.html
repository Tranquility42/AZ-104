Configurer le Stockage Blob

Conteneurs, accès anonyme, niveaux chaud → archive, règles de cycle de vie, réplication d'objets, types de blobs et outils d'envoi. Les notions marquées ➕ examen complètent le module.

⏱ Lecture : 9 min · module complet 🎯 Durées 30 / 90 / 180 jours : à savoir par cœur
💡
À retenir : compte → conteneur → blob. 4 niveaux : Hot (accès fréquent), Cool (30 j min), Cold (90 j min), Archive (180 j min, hors ligne, heures pour relire). Les règles de cycle de vie déplacent ou suppriment selon l'âge. La réplication d'objets exige le contrôle de version des deux côtés.

Pour s'en souvenir : la cour de remorques 🚛

📦 Ranger

  • Compte = la cour · conteneur = une remorque · blob = une palette dedans
  • Pas de palette par terre : tout blob est dans un conteneur
  • Blob de blocs = palette ordinaire (photos, PDF, vidéos)
  • Blob d'ajout = le carnet de bord : on ajoute des lignes à la fin (journaux)
  • Blob de pages = le disque d'une VM, lu et écrit au hasard

🌡️ Les niveaux

  • Chaud = le quai de chargement : cher à occuper, rapide à servir
  • Froid / sporadique = l'entrepôt du fond : moins cher, sortir coûte plus
  • Archive = l'entrepôt hors-ville : presque gratuit, mais des heures pour ramener la palette
  • Cycle de vie = la règle du contremaître : « après 30 jours sans bouger, au fond ; après 1 an, hors-ville »

1 · Conteneurs et accès anonyme

📛 Règles de nom du conteneur

  • Minuscules, chiffres, tirets
  • Commence par une lettre ou un chiffre
  • 3 à 63 caractères
  • Nombre illimité de conteneurs et de blobs

🔓 Niveau d'accès public

  • Privé (défaut) : aucun accès anonyme
  • Blob : lecture anonyme des blobs, sans lister
  • Conteneur : lecture et liste anonymes
  • ⚠️ Ces niveaux ne marchent que si « Autoriser l'accès anonyme aux objets blob » est activé sur le compte. Désactivé = tout reste privé

3 · Les règles de cycle de vie

⚙️ Ce qu'elles font

  • Comptes GPv2 et Premium blobs de blocs
  • Si « plus de N jours » depuis la dernière modification (ou le dernier accès) alors : déplacer vers cool, cold ou archive, ou supprimer
  • Agissent aussi sur les versions précédentes et les instantanés
  • Remettre automatiquement en chaud un blob froid qu'on relit
  • Filtres : tout le compte, des conteneurs, un préfixe de nom, des balises d'index
  • ➕ La règle tourne une fois par jour : jusqu'à 24 h pour voir l'effet

➕ La règle en JSON

{ "rules": [ {
  "name": "manifestes-vieillissent",
  "enabled": true,
  "type": "Lifecycle",
  "definition": {
    "filters": { "blobTypes": ["blockBlob"],
                 "prefixMatch": ["manifestes/"] },
    "actions": { "baseBlob": {
      "tierToCool":    { "daysAfterModificationGreaterThan": 30 },
      "tierToArchive": { "daysAfterModificationGreaterThan": 365 },
      "delete":        { "daysAfterModificationGreaterThan": 2555 }
    } } } } ] }

4 · La réplication d'objets

  • Copie asynchrone de blobs d'un conteneur source vers un conteneur destination, souvent dans un autre compte ou une autre région
  • Copie le contenu, les métadonnées et les versions. Pas les instantanés
  • Il faut le contrôle de version activé des deux côtés. ➕ Et le flux de modification (change feed) sur la source
  • Niveaux chaud, cool ou cold (pas archive), différents de chaque côté si on veut
  • Une stratégie nomme les deux comptes ; elle contient des règles (un conteneur source → un conteneur destination)
  • Pour : lire plus près des clients, traiter les mêmes données dans plusieurs régions, ne copier que les résultats, archiver la copie
  • ➕ Différence avec GRS : GRS copie tout le compte vers la région jumelée imposée ; la réplication d'objets copie les conteneurs que tu choisis, vers la région que tu choisis

⚠️ Le type de blob ne change plus après la création. 💸 Prix : volume stocké + nombre et type d'opérations + transfert sortant + redondance choisie + réplication géo. Plus c'est froid, moins le Go stocké coûte, plus la lecture et les transactions coûtent. Changer un blob vers un niveau plus chaud = on paie la lecture de toutes les données.

6 · L'exercice : site web public

  1. Créer un compte hautement disponible (RA-GRS)
  2. Autoriser l'accès anonyme sur le compte
  3. Créer un conteneur public avec le niveau Blob (lecture anonyme)
  4. Activer la suppression réversible (soft delete) pour restaurer un fichier effacé
  5. Activer le contrôle de version des blobs
az storage account create -g rg-labo -n sitepublic123 --sku Standard_RAGRS --allow-blob-public-access true
az storage container create --account-name sitepublic123 -n public --public-access blob --auth-mode login
az storage blob upload --account-name sitepublic123 -c public -f logo.png -n logo.png --auth-mode login
az storage blob service-properties delete-policy update --account-name sitepublic123 --enable true --days-retained 7
az storage account blob-service-properties update -g rg-labo -n sitepublic123 --enable-versioning true
azcopy copy './images/*' 'https://sitepublic123.blob.core.windows.net/public?<SAS>' --recursive

🚛 Appliquer à Optifuel

Le vieillissement des manifestes, réglé une fois pour toutes.

  • Conteneur manifestes en Privé : jamais d'accès anonyme pour des documents de douane.
  • Règle de cycle de vie : chaud le premier mois (le chauffeur et le répartiteur les consultent), cool ensuite, archive après un an. La durée de conservation légale, c'est à toi de la vérifier : ta nouvelle job de conformité tombe pile là.
  • Activer contrôle de version + suppression réversible : un manifeste écrasé ou effacé par erreur se récupère.
  • Les PDF de rapports de voyage : blobs de blocs. Les journaux de l'app : blobs d'ajout.

Pièges d'examen

🪤« Je veux récupérer un blob archivé dans la minute. »Archive = des heures. Même en priorité haute, compte jusqu'à 1 h. Pour un accès immédiat, garde-le en cool ou cold.
🪤« Mon conteneur est en niveau Blob mais l'URL refuse l'accès anonyme. »Vérifie le réglage du compte « Autoriser l'accès anonyme aux objets blob ».
🪤« Je supprime un blob cool après 10 jours, sans frais. »Durée minimale 30 jours : frais de suppression anticipée.
🪤« La réplication d'objets copie aussi mes instantanés. »Non : contenu, métadonnées et versions seulement.
🪤« La réplication d'objets marche sans rien activer. »Il faut le contrôle de version sur la source et la destination (et le flux de modification sur la source).
🪤« Je transforme mon blob de blocs en blob d'ajout. »Le type est fixé à la création.
🪤« 10 To à envoyer avec une connexion lente : AzCopy. »Trop lent : Data Box (envoi de disques par la poste).

Mini-quiz

Encart Terraform

🟪 Conteneur privé + règle de cycle de vie

resource "azurerm_storage_container" "manifestes" {
  name                  = "manifestes"
  storage_account_id    = azurerm_storage_account.manifestes.id
  container_access_type = "private"   # blob, container
}
resource "azurerm_storage_management_policy" "cycle" {
  storage_account_id = azurerm_storage_account.manifestes.id
  rule {
    name    = "vieillissement"
    enabled = true
    filters {
      prefix_match = ["manifestes/"]
      blob_types   = ["blockBlob"]
    }
    actions {
      base_blob {
        tier_to_cool_with_days_since_modification_greater_than    = 30
        tier_to_archive_with_days_since_modification_greater_than = 365
      }
    }
  }
}
